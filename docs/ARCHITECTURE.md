# Архитектура: почему модульный монолит

## Было

Три FastAPI-сервиса (`auth_service`, `task_management_service`, `solution_service`) с отдельными базами MySQL, которые общались по HTTP.

Что это стоило:
- **N+1 по сети.** Список попыток делал на каждую строку 3 HTTP-запроса (задача, тема, автор). 100 попыток = 300 запросов.
- **Нет целостности данных.** Ссылки между сервисами без внешних ключей: удалённая задача ломала историю попыток.
- **Каждый запрос ходил в auth-сервис** за пользователем, падение auth клало всё.
- Три конфига, три деплоя, CORS между сервисами, жёстко прописанные `127.0.0.1:800X` во фронтенде.

Для команды из одного-двух человек и нагрузки до десятков тысяч пользователей микросервисы дают только накладные расходы.

## Стало

Одно приложение FastAPI, внутри — модули с чёткими границами:

| Модуль | Отвечает за | Таблицы |
|---|---|---|
| `auth` | регистрация, вход, refresh/logout | `refresh_tokens` |
| `users` | профиль, аватар, роли, блокировка | `users` |
| `content` | предметы, темы, задачи | `subjects`, `themes`, `tasks` |
| `solutions` | попытки, автопроверка, оценки | `attempts` |
| `stats` | статистика и рейтинг (только чтение) | — |

Правила, которые сохраняют возможность потом разрезать монолит:
1. Модуль меняет только свои таблицы. Чужие данные читает через JOIN в своих запросах.
2. SQL лежит в `queries.py` модуля — видно, какие таблицы он трогает.
3. Общий код только в `app/` (`db`, `security`, `deps`, `storage`).

Если когда-нибудь, например, проверка решений начнёт упираться в CPU (проверка кода, ML), модуль `solutions` выносится в отдельный сервис с очередью — остальное не меняется.

## Почему чистый SQL, а не ORM

- Запросы видны целиком, их легко профилировать через `EXPLAIN`.
- Один запрос с JOIN вместо ленивых подгрузок.
- asyncpg — самый быстрый драйвер PostgreSQL для Python.
- Плейсхолдеры `$1, $2` — нативный синтаксис PostgreSQL, SQL-инъекции исключены: значения никогда не вклеиваются в строку.

Цена — миграции пишутся руками (`app/migrations/NNN_*.sql`) и применяются при старте под advisory-lock.

## Безопасность (исправлено по сравнению со старой версией)

- Роль при регистрации всегда «ученик»; учителей назначает админ.
- Refresh-токен проверяется по типу и одноразовый (ротация), хранится только его `jti`.
- В БД больше не пишется `SECRET_KEY`; приложение не стартует без ключа ≥ 32 символов.
- Блокировка пользователя сразу отзывает все его сессии.
- Загрузки проверяются по сигнатуре файла (PNG/JPEG/GIF/WebP), имена генерируются сервером.
- Правильный ответ не отдаётся ученику до верного решения.
- Ограничение: 10 попыток в минуту на задачу.
